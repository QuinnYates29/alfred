# D1 — dispatch an agent straight from a prompt, everywhere

Repo: alfred (TypeScript ESM server in src/, React dashboard in web/src, Electron Mac app in app/src, CLI in src/cli*).
Goal: one syntax that starts an agent run from a single prompt on every surface:

    !<persona> <prompt>      e.g.  !coder add a /health endpoint to ~/repos/foo
    !@<persona> <prompt>     same (the @ is optional)
    ! <prompt>               persona alfred (the default: it plans and delegates)

`<persona>` counts only if it is a known persona name (case-insensitive); otherwise the whole text after `!` is the
prompt for alfred. `!!` at the start is NOT a dispatch (Mac quick bar uses `!!` as a priority marker).

## 1. Server — new `src/dispatch.ts`
- `parseDispatch(text: string, personas: string[]): { persona: string; prompt: string } | null` — pure. Returns null if
  the text does not start with a single `!`, or the prompt is empty. Trims. Multi-line prompts allowed.
- `titleFor(prompt)`: first non-empty line, collapsed whitespace, max 80 chars (cut at a word boundary + `…`).
- `dispatchPrompt(store, personas: Map<string, Persona>, input: { prompt: string; persona?: string; repo?: string;
  node?: string; source: string })` → `{ goal, task, persona }`. Unknown persona → throw `unknown persona: x`.
  Uses `createGoalWithRoot` from `src/ops.js` with `{ title: titleFor(prompt), spec: prompt, persona, repo }` (persona default
  `alfred`), then `store.setGoalMeta(goal.id, { source, ...(node && node !== 'local' ? { node } : {}) })`.
  No acceptance checks are ever set here.
- Route in `src/server/app.ts` (next to `r.post('/goals'…)`, same auth as the rest of /api/v1): `POST /dispatch`,
  body either `{ text }` (parsed with parseDispatch; if it does not parse, treat the whole trimmed text as an alfred prompt)
  or `{ prompt, persona?, repo?, node? }`. `source` = `'dashboard'` unless body.source is one of
  `mac-quick|cli|dashboard` (never trust other values). Empty prompt → 400. Returns 201 `{ goal, task, persona }`.
  Also `GET /dispatch/help` → `{ personas: [{name, description}], syntax: '!<persona> <prompt>' }`.

## 2. Dashboard — `web/src/components/CommandPalette.jsx`

- When the query starts with `!`: the FIRST result is `Dispatch to <persona>: “<prompt>”` (icon `zap`, hint `run`),
  using a client-side copy of the parse rules; running it POSTs `/api/v1/dispatch` `{ text: q }` via the `api` helper
  (check `web/src/api.js` for how POST bodies are sent) and then `go('/goal/' + goal.id)`. On error, show the message
  inline in the palette instead of closing (keep palette open; a small `.error` line under the input).
- For any other non-empty query, after the existing `Ask alfred` row add one row per persona
  `Run with <persona>: “<q>”` (icon `zap`, hint `run`) that dispatches `{ prompt: q, persona }` the same way.
- Placeholder text: `Search, jump, ask alfred — or !coder <task> to run an agent…`.
- `web/src/views/Chat.jsx` composer: if the message starts with a single `!`, do NOT send it to chat; POST
  `/api/v1/dispatch {text}` and show a local notice line in the thread area: `Started <persona> → <goal title>` linking to
  the goal (`href('/goal/<id>')` — see how Chat.jsx / App.jsx build links). Keep it minimal.
- Run `npm --prefix web run build` to make sure it compiles (web has its own node_modules; if missing, `npm --prefix web install`).

## 4. Slack — `src/slack/handlers.ts`, `src/slack/index.ts`
- Add to `HandlerCtx`: `dispatch?(text: string): { goalId: string; slug: string; title: string; persona: string }`
  (throws on bad input) and `follow?(goalId: string, onDone: (status: string, summary: string) => void): void`.
  Wire both in `src/slack/index.ts`: dispatch = `dispatchPrompt(deps.store, deps.personas, { ...parsed, source: 'slack' })`
  (parse with `parseDispatch(text, [...deps.personas.keys()])`; read deps.personas lazily at call time — it is filled
  after modules are created). follow = subscribe `deps.store.onEvent` for `kind === 'goal_status'` on that goal id with
  status `done` or `failed`, call onDone once with a summary (the root task's `result` or `reason`, ≤ 1500 chars), then
  unsubscribe; also unsubscribe after 24 h.
- DMs and @mentions (handleEvent): if the text parses with parseDispatch (use the ctx persona list: add
  `personaNames?(): string[]` to HandlerCtx), dispatch instead of chatting. Reply in the same place:
  `:rocket: Started *<persona>* → <title>` plus `<dashboardUrl>/#/goal/<id>` if `deps.dashboardUrl` is set (pass a
  `dashboardUrl?` on ctx). When it finishes, post in the same thread/place: `:white_check_mark: done — <title>\n<summary>`
  or `:x: failed — <title>\n<summary>` (convert with `toMrkdwn`).
- `/alfred run <persona> <prompt>` and `/alfred run <prompt>` in handleSlash: same as `!<persona> <prompt>`; ack text is the
  "Started" line; on finish, `ctx.postUrl(response_url, { text: … })`.
  Update the usage hint in `deploy/slack-manifest.yaml` to mention `run coder <task>`.
- Unauthorized users are refused exactly as today (check `allowed` first).

## 5. CLI — `src/cli.ts` (+ a helper in `src/cli/`)
- `alfred run [persona] "<prompt>" [--repo P] [--node N] [--wait]`: if the first positional is a persona name
  (fetch `GET /dispatch/help` for names) and there is a second positional, it is the persona; else everything is the prompt
  (persona alfred). Also accept `alfred run "!coder fix it"`. POST `/dispatch` `{ prompt, persona, repo, node, source:'cli' }`.
  Print `started <persona> → <slug> (<goal id>)`. With `--wait`, poll `GET /goals/<id>` every 3 s until the goal status is
  `done` or `failed`, printing each new task status change once; then print the root task result/reason and exit 0 (done)
  or 1 (failed). Add the command to the USAGE text next to `ask`/`chat`.
