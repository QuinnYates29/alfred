# V1 — agents write documentation into Quinn's Obsidian vault (on his Mac) via the alfred node

Repo: alfred. Quinn's Obsidian vault is a folder of Markdown files on his MacBook, which runs the alfred node (the
Electron app's built-in node, or `alfred-node` = `src/node/client.ts`). Obsidian picks up file changes live. Build a
`vault` capability on the node and a `vault` agent tool on the server.

Quinn's rules: agents may create/append pages freely inside an AGENT FOLDER of the vault (default `Alfred/`); writing
anywhere else in the vault, or moving pages (from or to anywhere outside the agent folder), needs his approval.

## 1. Node side — `src/node/client.ts` (+ `src/node/protocol.ts` for shared helpers)
- New option `vault?: string` (absolute path; CLI flag `--vault <path>`, `~` expanded) → adds cap `vault` and reports
  `vault: { name: basename }` in the hello message (NOT the absolute path). The vault is NOT added to `roots`: general fs/exec
  ops (coder workspaces on the Mac) must never reach it, and vault ops never reach the roots.
- New ops (only when cap `vault`), all paths are vault-RELATIVE, `.md` files only for read/write/append/move, no `..`,
  no absolute paths, no hidden segments (`.obsidian`, `.trash`, `.git` — refuse any segment starting with `.`), resolved with
  the same realpath containment used by `guardRoot` / `containedPath` (`src/pathguard.ts`) against the vault dir:
  - `vaultList { path?: string, recursive?: boolean }` → `{ entries: [{ path, dir, size, mtime }] }` (max 2000 entries; skip dot dirs).
  - `vaultRead { path }` → `{ content, mtime }` (≤ 1 MB).
  - `vaultSearch { query, max?: 20 }` → case-insensitive substring search over `.md` files (skip dot dirs; stop after 5000
    files / 50 MB read) → `{ hits: [{ path, line, text }] }`.
  - `vaultWrite { path, content, overwrite?: boolean }` → creates parent dirs; refuses to overwrite an existing file unless
    `overwrite:true`; atomic (tmp + rename); ≤ 512 KB.
  - `vaultAppend { path, content }` → appends `\n` + content to an existing page (creates if missing).
  - `vaultMove { from, to }` → rename within the vault; refuses if `to` exists.
- Add the ops to the node op allowlist/handler (see `handleOp`), with unit-testable pure helpers (`vaultResolve(vaultDir, rel,
  {write})` etc.) exported for tests.
- Electron app (`app/src/node.cjs`, `app/src/settings.cjs`, `app/src/settings.html`): a "Obsidian vault folder" field in the
  node section (absolute path; a "Choose…" button using `dialog.showOpenDialog({properties:['openDirectory']})` via the
  existing IPC pattern in `app/src/main.cjs`/`preload.cjs`), stored as `settings.node.vault`, passed as `--vault <path>`.
  Update `test/unit/app-node.test.ts` expectations if they assert the exact arg list.

## 2. Server side — `src/vault/` module (copy the structure of `src/comms/index.ts`: module + `vaultToolStubs()` for allTools)
- Policy `config/vault.yaml` (read fresh via `powersRoot(deps)`; missing → defaults) + `config/vault.example.yaml`:
  ```yaml
  node: ''            # node name; '' = the first connected node with the `vault` cap
  agentFolder: Alfred # agents write here freely (created on first write)
  maxPageBytes: 200000
  ```
- Agent tool `vault` (caps `['fs-write']`, kind 'write'). Description: "Quinn's Obsidian vault (Markdown). op: list | read
  | search | write | append | move. Writing inside the agent folder (<agentFolder>/) is automatic; anywhere else, and every
  move, needs Quinn's OK. Search before writing to avoid duplicates; link related pages with [[Page Name]]."
  Params `{ op, path?, content?, query?, to?, overwrite?, recursive? }`.
  - list/read/search → node call (no approval). Output: listing lines / page content (cap 16 k chars with a note) / hits.
  - write/append: path normalised (add `.md` if missing). Inside `agentFolder/` → run directly. Outside → go through
    `gated({deps, tool: ctx}, 'vault.write', \`vault ${op} ${path}\`, run, { info: <the full content>, bind: sha256(op+path+content) })`
    (`gated`/`sha256` from `src/powers/gate.js`).
  - move: always gated unless BOTH `path` and `to` are inside the agent folder; action `vault.move`, detail `vault move A → B`.
  - Every successful write/append/move → store event `vault` `{ op, path, to?, bytes, auto: boolean }` on the task's goal
    (never the content), and the result line says `saved to Obsidian: <path>`.
  - Node offline / no node with `vault` cap → throw/return via `NodeOfflineError` semantics so a goal task parks `blocked`
    (see `parkIfNodeOffline` in `src/runtime/tools.ts`); in chat return `{ok:false, output:'the Mac with the vault is offline'}`.
  - The node call API: read how `src/comms/index.ts` calls `deps.nodes.call(node, op, args)` and how it picks a node by cap.
- Routes: `GET /vault/status` → `{ node, online, vaultName, agentFolder }`; `POST /vault/publish` `{ path, content }` —
  Quinn's own "Save to vault" (dashboard): allowed anywhere, not gated, still node-guarded; used later by the goal Outputs panel.
- Capability card line in `src/powers/card.ts`. Do NOT edit personas/*.yaml.
- Dashboard: a "Vault" row in `web/src/views/system/NodesTab.jsx` showing which node serves the vault and its name/agent folder.

## Tests
- `test/unit/vault-node.test.ts`: the node-side helpers against a temp dir: containment (`..`, absolute, symlink escape,
  `.obsidian/x.md`, non-`.md`), list/read/search/write (no overwrite without flag)/append/move, size caps, and that general
  `readFile`/`writeFile` ops with a path in the vault dir are refused when the vault is not inside roots.
- `test/unit/vault-tool.test.ts`: the server tool with a fake `deps.nodes` (`list()` returning a node with caps
  ['vault'], `call()` recording ops): write inside `Alfred/` runs without an approval; write outside parks for approval (goal
  task) — copy the gate test setup from `test/unit/powers-p21a.test.ts` — and runs once approved; move rules; offline node parks;
  events carry no content.
