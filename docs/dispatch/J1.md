# J1 — Jira integration: pull issues onto the board + a tightly limited `jira` agent tool

Repo: alfred (TypeScript ESM, Node 22, vitest, express 5). Quinn's Jira Cloud is a shared WORK site
(`https://delresearch.atlassian.net`, 45 projects, coworkers see everything). Agents must only get a small set of
pre-defined, rate-limited abilities. Nothing may bulk-create, bulk-edit, delete, transition, reassign or touch projects
outside an allowlist.

Copy the structure of the comms module (`src/comms/index.ts`: `createCommsModule`, `commsToolStubs`, the `bound`
WeakMap, `record()` events, env creds read from `deps.env`, router) — read it first.

## 1. Config
- Credentials from `deps.env` (never logged, never in outputs/events/errors): `JIRA_SITE` (e.g.
  `https://delresearch.atlassian.net`, must be https and end in `.atlassian.net`), `JIRA_EMAIL`, `JIRA_API_TOKEN`.
  Auth = HTTP Basic `email:token`. Missing → module still loads; tool/route answer `Jira is not configured (set
  JIRA_SITE, JIRA_EMAIL, JIRA_API_TOKEN in ~/.config/alfred.env)`.
- Policy file `config/jira.yaml` (path: `join(powersRoot(deps), 'config', 'jira.yaml')`, `powersRoot` from
  `src/powers/gate.js`), read fresh on each use; missing/broken = the SAFE defaults below (fail closed). Also add
  `config/jira.example.yaml` documenting every key:
  ```yaml
  # Agents may create tickets / comment ONLY in these projects (empty = agents can't create or comment at all).
  projects: []
  issueTypes: [Task, Bug]        # allowed types for agent-created tickets
  limits:
    createsPerDay: 5             # across all agents, rolling 24 h
    commentsPerDay: 20
    searchesPerHour: 60
  import:                        # pull Jira → board (server-side, never writes to Jira)
    enabled: false
    jql: 'assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC'
    board: ''                    # board key; '' = default board
    everyMinutes: 15
    max: 50                      # per sync
  ```
  Validate: `projects` = array of `^[A-Z][A-Z0-9_]{1,9}$`; numbers clamped (createsPerDay ≤ 50, commentsPerDay ≤ 200,
  searchesPerHour ≤ 600, everyMinutes 5..1440, max 1..100).

## 2. `src/jira/client.ts`
`jiraClient(env, fetchImpl = fetch)` → `null` if not configured, else an object with:
- `search(jql, max)` → `POST /rest/api/3/search/jql` body `{ jql, maxResults: min(max,50), fields: [summary,status,
  priority,duedate,issuetype,project,assignee,updated,labels] }` → `{ issues: JiraIssue[] }`
  (`JiraIssue = { key, summary, status, statusCategory ('new'|'indeterminate'|'done'), priority, due, type, project, assignee, updated, url }`,
  url = `${site}/browse/${key}`).
- `get(key)` → `GET /rest/api/3/issue/{key}?fields=…,description` → JiraIssue + `description` as plain text (flatten ADF:
  walk `content` arrays collecting `text` nodes, newline between paragraphs; ≤ 4000 chars).
- `create({ project, type, summary, description, labels })` → `POST /rest/api/3/issue` with description in ADF (one
  paragraph per line of text) → `{ key, url }`.
- `comment(key, text)` → `POST /rest/api/3/issue/{key}/comment` (ADF body) → `{ id }`.
- `myself()` → `GET /rest/api/3/myself` → `{ accountId, displayName }` (used by status).
All: 20 s timeout, `Accept: application/json`, errors → throw `Error('Jira <status>: <errorMessages joined, ≤300 chars>')`
with NO credentials in the message. Validate keys with `^[A-Z][A-Z0-9_]{1,9}-\d{1,7}$` before building any URL.

## 3. The agent tool `jira` (`src/jira/tool.ts`), caps `['network','people']`, kind `'write'`
Schema description (keep short): `Quinn's work Jira. op: search|get|create|comment. create/comment need Quinn's OK and are limited to allowed projects.`
Params: `op` (enum), `jql`, `key`, `project`, `type`, `summary`, `description`, `text`, `max`.
- `search`: `jql` required, ≤ 500 chars, `max` default 10 cap 20. Rate: `limits.searchesPerHour`. Output: one line per
  issue `KEY [status] (type, priority) summary — due X` + total line. Reading is not gated.
- `get`: one issue with description.
- `create`: project must be in `policy.projects` (else refuse listing the allowed ones), type in `issueTypes`,
  summary 3..200 chars single line, description ≤ 4000. Daily cap from store events (see §5) → refuse when reached
  (`daily limit of N Jira tickets reached`). Duplicate guard: refuse if a ticket with the identical summary was created by
  alfred in the last 7 days (from the events). Label every ticket `alfred`; append to the description the line
  `— created by alfred (Quinn's assistant)`. Then run through the approval gate:
  `gated({deps, tool: ctx}, 'jira.create', \`jira create ${project}/${type}: ${summary}\`, run, { info: <project, type, summary, description> })`
  (import `gated` from `src/powers/gate.js`). Output `created KEY url`.
- `comment`: key's project must be in `policy.projects`; text 1..2000; daily cap; gated with action `jira.comment`,
  detail `jira comment KEY: <first 200 chars>`, info = full text.
- Any other op (transition, delete, assign, edit, bulk…) → `{ok:false, output:'not allowed: jira supports search, get, create, comment only'}`.
- The tool never throws. Chat tasks (`ctx.taskId` starting `chat:`) use the same gate (gated handles both).

## 4. Import: Jira → board (`src/jira/sync.ts`)
`syncJira(deps, board, client, policy)` → `{ created: string[], updated: string[], closed: string[], errors: string[] }`:
- Board: `policy.import.board` or default. Ensure the board has a field `{ id: 'jira', name: 'Jira', type: 'url' }`
  (add via `board.updateBoard(key, { fields: [...existing, field] })` if missing).
- Run `client.search(policy.import.jql, policy.import.max)`. For each issue: find an existing (non-archived) item whose
  `fields.jira` equals the issue url.
  - Not found and not done → `board.createItem({ board, title: \`${key} ${summary}\`, description: \`${url}\n\n${desc?}\`,
    labels: ['jira', project.toLowerCase()], priority: map(Highest/Blocker→urgent, High→high, Medium→medium, Low/Lowest→low, else none),
    due, fields: { jira: url } }, 'jira')`. Don't fetch descriptions per issue (keep it one API call).
  - Found → if title/due/priority changed in Jira, `updateItem` those only (never touch status, labels Quinn added, etc.).
    If the Jira statusCategory is `done` and the item isn't in a done column, move it to the board's first `done`-kind
    column (look at `Column.kind`) and record it in `closed`.
- Never deletes items. Never writes to Jira.
- `createJiraModule(deps)`: timer every `import.everyMinutes` when `import.enabled` and configured (first run 30 s after
  start); `timer.unref()`; errors recorded, never thrown. Emits store event `jira` `{kind:'sync', created, updated, closed, errors}`
  via `deps.store.appendEvent('', null, 'jira', …)`.

## 5. Usage accounting
Every create/comment/search outcome → `deps.store.appendEvent('', null, 'jira', { kind: 'create'|'comment'|'search', ok, key?, summary?, project? })`.
Counts for limits = events of kind `jira` in the window with `ok:true` (use `deps.store.events('')` filtered by `kind`
and timestamp — check the Event shape in `src/types.ts`). Put the counting in one exported helper `usage(deps, now)` →
`{ createsToday, commentsToday, searchesHour }`.

## 6. Routes (module router, mounted under /api/v1 like comms)
- `GET /jira/status` → `{ configured, site, user?: displayName, policy (without anything secret), usage, lastSync? }`
  (`user` via `myself()` cached 10 min; failures → `error` field).
- `POST /jira/sync` → runs the import now (even if `import.enabled` is false; still requires config) → the sync result.
- `POST /jira/items/:key/ticket` (Quinn from the dashboard; not gated, but project must be in policy.projects and the
  daily cap still applies) body `{ project, type }` → creates a ticket from the board item's title/description, sets the
  item's `jira` field to the new url, adds the `jira` label → `{ key, url }`.
