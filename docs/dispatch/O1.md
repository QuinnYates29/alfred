# O1 — agent outputs: an `output` tool whose results show up in the goal view

Repo: alfred (TypeScript ESM server in src/, React dashboard in web/src). Quinn cannot find what agents produce (e.g. a
research report lives only in `~/.alfred/work/<goal>/REPORT.md`). Add first-class goal OUTPUTS.

## 1. Store — `src/store.ts` (follow the existing table/migration/prepared-statement style)
- Table `goal_outputs(id TEXT PK, goalId TEXT NOT NULL, taskId TEXT, name TEXT NOT NULL, kind TEXT NOT NULL,
  content TEXT NOT NULL, bytes INTEGER NOT NULL, createdAt INTEGER NOT NULL, updatedAt INTEGER NOT NULL)`, unique index on
  `(goalId, name)`; `CREATE TABLE IF NOT EXISTS` so existing DBs migrate.
- Methods (add to the Store interface): `putOutput({ goalId, taskId?, name, kind, content })` → upsert by (goalId, name),
  returns the row; `outputs(goalId)` → rows WITHOUT content, newest first; `getOutput(id)` → row with content;
  `deleteOutput(id)`. Emit event `output` on the goal `{ id, name, kind, bytes, taskId }` (never the content).
- Validation: name 1..120 chars, no `/` or control chars (trim); kind ∈ `markdown|text|json|csv|html-code` (default
  markdown); content ≤ 512 KB (else throw `output too large`). `deleteGoal` also deletes the goal's outputs.

## 2. Agent tool `output` — in `src/runtime/tools.ts` builtinTools (kind 'write', no caps)
Schema: `output` — "Publish a deliverable to the goal page (Quinn reads it there). Use for reports, summaries, tables,
drafts. Same name = update." Params `{ name: string, content: string, kind?: enum }`. Resolves the store with
`storeForTask(ctx.taskId)` (already used in this file), the goal from the task. Returns `published "<name>" (N chars) —
visible on the goal page`. Errors → `{ok:false}`.
- Tool must also work for chat (`ctx.taskId` = `chat:<thread>` has no goal) → return `{ok:false, output:'output is for goal
  tasks; in chat, answer directly'}`.

## 3. Report goals publish automatically — `src/runtime/agent.ts` doFinish
Where the runtime writes the finish summary to REPORT.md for report goals (`isReportCheck`), also
`o.store.putOutput({ goalId: task.goalId, taskId, name: 'Report', kind: 'markdown', content: summary })`.

## 4. API — `src/server/app.ts` (same auth as the rest of /api/v1)
- `GET /goals/:id/outputs` → list (no content). `GET /goals/:id/outputs/:oid` → full row. `GET /goals/:id/outputs/:oid/raw`
  → the content with a content-type from kind (`text/markdown; charset=utf-8`, `text/plain`, `application/json`, `text/csv`)
  and `Content-Disposition: attachment; filename="<name>.<ext>"` (sanitize the filename). `DELETE /goals/:id/outputs/:oid`.
- `GET /goals/:id` (goal detail) additionally returns `outputs` (the list).
- Add the event kind to the documented kinds list in app.ts (`{ kind: 'output', meaning: … }`).

## 5. Goal view — `web/src/views/GoalDetail.jsx` (+ GoalDetail.css)
- When the goal has outputs: an **Outputs** card at the TOP of the page (above tasks). One tab per output (name + kind),
  the newest selected. Markdown kind renders with the existing `Markdown` component from `web/src/ui/index.jsx` (it is
  sanitized); json → pretty-printed `<pre>`; csv → a simple table (first 200 rows); text/html-code → `<pre>`.
- Actions per output: Copy (clipboard), Download (fetch `/raw` via the `api` helper as text → Blob download, because
  the token is a header), Delete (confirm dialog, use the existing `useToast().confirm`).
- Live: refetch on `output` events for this goal (see how GoalDetail already subscribes to events with `useResource`'s
  `on:` / live helpers).
- The goals LIST (`web/src/views/Goals.jsx`) shows a small doc icon + count when a goal has outputs (add `outputs`
  count to `goalSummary` in `src/ops.ts`).
- Board item drawer (`web/src/views/board/ItemDrawer.jsx`): under linked goals, list their outputs as links to the goal page.
