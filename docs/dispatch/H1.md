# H1 — chat history dataset (with right/wrong feedback) + a Private chat mode

Repo: alfred (TypeScript ESM server in src/, React dashboard in web/src, CLI in src/cli*). Read first:
`src/chat/engine.ts` (the turn loop), `src/chat/store.ts` (sqlite threads/messages), `src/chat/routes.ts`,
`src/models.ts` (ModelRegistry: resolve/llm/list), `web/src/views/Chat.jsx`, `src/slack/handlers.ts`.

Two features:
A. Every chat turn (and every finished goal) is recorded as training/eval data in JSONL files on the Spark's disk, and Quinn
   can mark answers right/wrong (+ an optional correction) so he can optimise prompts/models/fine-tunes later.
B. A per-thread **Private** toggle: nothing about a private thread goes anywhere except the chat itself and the LOCAL
   model on the Spark.

## A. Dataset

### Storage — new `src/chat/dataset.ts`
- Dir: `env.ALFRED_DATASET_DIR` or `~/.alfred/datasets` (expand `~`). Files: `chat-YYYY-MM.jsonl`,
  `feedback-YYYY-MM.jsonl`, `goals-YYYY-MM.jsonl`, and `prompts/<sha256>.txt` (system prompts stored once, by hash).
  Dirs created 0700, files 0600 (see `src/secure-fs.ts` for existing helpers; append with `fs.appendFileSync` + mode).
- Writing must never throw into the caller and never block a reply (try/catch, sync append is fine).
- `recordTurn(rec)`, `recordFeedback(rec)`, `recordGoal(rec)`, `readRecords(kind, { since?, limit? })`,
  `purgeThread(threadId)` (rewrites the chat + feedback files without that thread's lines; atomic via temp file + rename),
  `stats()` → `{ turns, feedback: { up, down }, byModel: { [model]: { turns, up, down, avgLatencyMs } }, bytes }`.
- Turn record (one line per assistant reply):
  `{ v:1, type:'turn', id:<assistant message id>, ts, threadId, source:'dashboard'|'slack'|'cli'|'mac'|'api',
     model:{ name, model, baseUrl }, systemSha, messages:<exact LLMMessage[] of the FINAL model call, incl. tool calls and
     tool results>, reply, actions, llmCalls, usage:{ promptTokens, completionTokens } (summed over calls), latencyMs,
     ok, error? , deniedTools:[…] }`.
- Feedback record: `{ v:1, type:'feedback', ts, threadId, messageId, rating:'up'|'down'|null, note?, correction? }`
  (null = cleared). Latest one per messageId wins when reading.
- Goal record, written on `goal_status` done/failed (subscribe `store.onEvent` in the chat module or a small
  `src/datasetGoals.ts` started from the module): `{ v:1, type:'goal', ts, goalId, title, spec (goal body ≤ 20000),
  status, personas:[…], tasks:[{ id, persona, status, result?, reason? , usage? }], durationMs, source: goal.meta.source }`.
  Skip goals whose `meta.private === true`.

### Engine changes (`src/chat/engine.ts`)
- Track per turn: model spec used (add a method on ModelRegistry if needed, e.g. `resolve('planner')` already returns
  the ModelSpec), summed usage from each `llm.chat` response, number of calls, latency, final messages, error.
- `send(threadId, text, o?: { by?: string; source?: string })` — pass `source` through; routes/Slack/CLI set it
  (Slack handlers pass `'slack'`; dashboard route `'dashboard'`; `POST /chat` one-shot → `body.source` if one of
  `cli|mac|dashboard`, else `'api'`).
- After storing the assistant message, `recordTurn(...)` unless the thread is private.

## B. Private mode

- Thread gets `private INTEGER NOT NULL DEFAULT 0` (guarded migration). `POST /chat/threads` accepts `{ private: true }`;
  `PATCH /chat/threads/:id { private: boolean }` toggles. When switching ON with `{ private: true, purge: true }`, also
  `purgeThread(id)` (removes earlier records). Thread JSON includes `private`.
- For a private thread, the engine:
  1. uses ONLY a local model: the planner model if its `baseUrl` host is `127.0.0.1`, `localhost` or `::1`; otherwise the
     first model in the registry with such a baseUrl; none → reply `⚠ Private mode needs a local model on the Spark; none
     is configured.` without calling any LLM. (`extra.llm` test override counts as local.)
  2. offers NO tools at all (tools list empty; any tool call the model still makes gets `tools are off in private mode`).
     No tools = no web, Slack, Jira, messages, notifications, goals, board writes, approvals or connectors.
  3. writes no dataset records (turns, feedback), no goal records, no `notice`/notify events, and emits `chat_progress`
     events WITHOUT a `tool` field (phase + threadId only — no content ever goes into events).
  4. adds one line to the system prompt: `Private conversation: you have no tools; answer from your own knowledge.`
- Slack: a Slack conversation can never be private (Slack is external). If a thread that is private is somehow resolved
  from a Slack key, refuse: reply `This conversation is private — continue it in the dashboard.` and do not call the engine.
  Add a `slack` guard in `src/slack/handlers.ts` (check `chat.getThread(id)?.private`).
- Server logs: make sure no code path logs message content for private threads (grep `console.` in src/chat and
  src/slack; content should not be logged for any thread — log ids/lengths only).
- The Mac app / dashboard notifications for chat replies (if any path emits a `notice` for a chat reply) must skip private threads.
- UI (`web/src/views/Chat.jsx`): a "Private" toggle (lock icon + label) in the thread header and on the new-thread control.
  When on: a subtle banner "Private — local model only, no tools, nothing saved to the dataset or sent to Slack/other services";
  thread list shows a lock icon. Turning it on for a thread with earlier messages asks (confirm dialog) whether to also
  delete that thread's earlier dataset records (→ purge:true).
- CLI: `alfred chat --private` and `alfred ask --private "..."` create a private thread.

## Tests — `test/unit/chat-dataset.test.ts` (temp dataset dir via env/extra; fake LLM from existing chat tests —
copy the setup from `test/unit/chat-progress.test.ts`)
- A normal turn writes one turn record with model/usage/latency/messages/source, file mode 0600, prompt file by sha.
- Feedback route stores rating on the message and appends a feedback record; null clears; stats counts up/down per model.
- Export route returns NDJSON; `since` filters.
- Goal done → goal record; goal with `meta.private` → none.
- Private thread: fake LLM receives `tools: []` and the private line in system; no dataset lines written; feedback on it
  not recorded; `chat_progress` events have no `tool`; with a registry whose planner is `https://api.example.com` and no
  local model → the refusal reply and the fake remote LLM is never called; with one remote + one local model → local used.
- PATCH private:true + purge:true removes that thread's earlier records and keeps others.
- Slack handler refuses a private thread.
